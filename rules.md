# Project Rules & Guidelines

These mandatory rules govern every step of this project:

## Mandatory Operational Rules

1. **Living Core Documentation**:
   Always maintain and continuously update the three core markdown files:
   - [`rules.md`](file:///c:/Users/asami/DOCS/Bujji/rules.md): Project rules, guidelines, and constraints.
   - [`outline.md`](file:///c:/Users/asami/DOCS/Bujji/outline.md): Architecture overview, project components, roadmap, and structure.
   - [`handoff.md`](file:///c:/Users/asami/DOCS/Bujji/handoff.md): Current status, recent changes, pending tasks, and context handover notes.

2. **Isolated Scratchpad & Testing Directory (`.antigravity/`)**:
   - A `.antigravity/` folder exists at the project root and is immediately ignored in [`.gitignore`](file:///c:/Users/asami/DOCS/Bujji/.gitignore).
   - Place **all** testing files, execution verification scripts, helper tools, benchmarks, experiments, and temporary scratch files exclusively inside `.antigravity/`.
   - Never commit or pollute the main project directory with temporary or test scripts.

3. **Clean & Sorted Project Structure**:
   - Keep the project root and subdirectories clean, modular, and systematically organized.
   - Avoid clutter, duplicate files, or orphaned assets.

4. **Continuous Git Versioning**:
   - Maintain Git version control with meaningful, conventional commit messages for each logical step or milestone.
   - Ensure working tree cleanliness and clear commit history.
